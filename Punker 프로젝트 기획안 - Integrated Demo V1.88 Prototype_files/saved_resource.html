1. Product Overview

MCN이 해결하는 일

MCN은 지갑 연결과 NFT 권한 판별을 시작점으로, 프로젝트별 미션 배정, 제출 검수, 보상 적립, Tier/Authority 반영까지 이어지는 운영형 플랫폼이다.

제품 한 줄 정의

사용자의 지갑 자산과 활동 자격을 판별하고, 프로젝트별 미션 참여 권한과 보상, 후속 서비스 진입 자격까지 연결하는 운영형 마케팅 플랫폼.

핵심 루프

지갑 연결 → 사용자 분류 → 권한별 미션 노출 → 제출 증빙 → 검수 → 보상 적립 → Tier 및 Authority 반영

3. Project & Mission Flow

프로젝트와 미션 구조

사용자는 자신이 보유한 프로젝트를 기준으로 대시보드와 미션 보드를 확인한다. 미션은 Type A / Type B / Type C로 나뉘고, 권한과 보상 정책이 다르게 적용된다.

My Store Dashboard

보유 NFT에 따라 남산타워, 을지로 갈비 같은 프로젝트 카드가 활성화된다. 카드에는 접근 상태와 적용 수익률, 현재 등급이 함께 표시된다.

Mission Board

선택한 프로젝트 기준으로 미션 목록을 보여주며, 보유하지 않은 프로젝트 미션은 참여할 수 없거나 제한된다.

미션 유형

Type A는 홀더 대상 기본 활동, Type B는 성장형 활동, Type C는 상위 Tier 대상 확장 활동으로 이해하는 것이 기준선이다.

5. Rewards, Milestone & Tier

보상과 등급

보상은 원장 단위로 분리 관리되고, NFT 보유량 기반 마일스톤과 Tier 구조가 함께 작동한다.

Reward Ledger

Essential / Growth / Bonus Ledger를 분리해 어떤 활동에서 어떤 자산이 쌓였는지 보여준다.

Milestone Logic

NFT 보유 수량이 5개 단위 기준에 도달할 때마다 미션 요구량이 압축되며, 30개 이상 구간은 VVIP 자문 리포트 Unlock 구조로 이어진다.

Tier & Authority

승인된 MCN 활동은 사용자 Tier와 Authority 입력으로 이어지며, MCN은 성장 시스템의 직접 입력원 중 하나다.

1. Console Overview

운영 콘솔의 역할

Ops Console은 일반 사용자 경험과 분리된 운영 전용 레이어다. 거래/정산/리스크/권위 정책을 읽고 조정하는 것이 목적이다.

핵심 질문

지금 어떤 거래가 진행 중인가? 어떤 계정이 위험한가? 어떤 GP가 어디서 왔고 어디로 갔는가? 권위 규칙은 어떤 기준으로 운영되고 있는가?

운영 원칙

사용자용 제품과 같은 화면 안에 있더라도 역할은 명확히 분리된다. Ops Console은 해석/관리/차단/조정의 화면이다.

3. Ledger & Pipeline

원장과 환전 파이프라인

GP 원장과 환전 상태 머신은 운영 콘솔의 첫 번째 축이다.

GP 원장 조회

MCN GP, Arena GP, Exchange spend를 같은 관점에서 읽고, 소스별 내역과 환전 거래 이력을 함께 본다.

API 3-step 시뮬레이터

requested → locked → deducted → settled 흐름을 상태 머신으로 설명하며, 네트워크 실패와 중복 요청, 정산 지연 같은 운영 시나리오도 다룬다.

requested → locked → deducted → settled - requested: 사용자가 환전 요청을 보냄 - locked: 가용 잔액을 잠금 - deducted: 실제 차감 처리 - settled: 외부 정산 완료
4. Risk & Account Control

리스크와 계정 제어

위험 계정을 선별하고 상태를 조정하는 흐름이다.

리스크 큐

유저별 점수, 레벨, 사유, 최근 업데이트를 한눈에 보고 우선순위를 정한다.

계정 상세 / 동결

선택한 계정의 점수 이력, 리스크 레벨, 관리자 메모를 보고 동결/해제를 실행한다. 동결 시 모든 API 요청 차단이 핵심 메시지다.

계정 GP 보유 현황

MCN GP, Arena GP, 합계, 환전 사용, 가용 잔액, 현재 상태를 같은 표에서 읽는다.

5. Authority Ops

권위 정책 운영

Authority를 계산하는 화면이 아니라, 운영 기준을 조정하는 레이어다.

EXP 단가 조정

MCN Additional Mission, Arena Win, Burn 등 소스별 기본 EXP를 조정한다.

Level Curve 조정

Level 1~100 누적 곡선을 조정하고 반영 타이밍을 관리한다.

Indirect EXP Ratio / Manual Grant

간접 EXP 비율과 상한을 조정하고, 운영자가 개별 유저에게 EXP를 수동 부여/차감할 수 있어야 한다.

6. Incidents & Response

인시던트 대응

단순 로그가 아니라, 어떤 사건이 있었고 어떤 조치가 이어졌는지를 설명하는 메뉴얼이다.

대량 환전 시도 감지

리스크 스코어 급등, 자동 보류, 관리자 동결 처리까지의 타임라인을 남긴다.

1. Unified Experience

Arena 제품 개요

현재 구현은 battle demo를 유지하되, 실제 게임이 연결될 때는 adapter가 session snapshot을 공급하고 이 페이지는 역할 기반 product shell로 동작합니다.

제품 한 줄 정의

실게임 세션, 서포터 개입, Authority 성장, 정산 정책을 하나의 연결된 Arena 경험으로 정리하는 제품 shell.

핵심 루프

NFT 홀더 자격 확인 → 덱/스쿼드 준비 → 실시간 배틀 → 서포터 개입 → 정산 → Authority 반영

2. 역할 구조

Player · Supporter · Operator

Arena는 세 가지 역할이 같은 세션 안에서 상호작용하는 구조입니다.

Player / Influencer

NFT 홀더인지, 아바타 인증이 유효한지, 현재 덱/스쿼드와 장비가 실제 게임 세션에 반영될 수 있는지 확인합니다.

Supporter / Spectator

서포터 아이템은 단순 구매가 아니라 live match에 이벤트를 쏘는 액션이어야 합니다. 현재 데모는 fallback이고, 실연동 시에는 event contract를 통해 반영됩니다.

Operator / Policy

정산 비율, Authority 적립 규칙, 외부 Punkvism 연동 상태는 제품 UI 안에서 읽히되 실제 결정권은 Ops 레이어가 가져갑니다.

3. 카드형 스쿼드 기준선

카드형 스쿼드 배틀 구조

Arena는 순수 CCG보다 카드형 스쿼드 배틀에 가깝습니다. 로스터 카드, 배치된 유닛, 무기, 서포트 이벤트를 각각 독립 상태로 보여주되 같은 세션 규칙으로 묶어야 합니다.
